# 음성 자막 시험 조사 — 비주얼 장면 1 (2026-10-02)

결정 D-5(음성 자막 넣지 않음)를 다시 보기 위한 조사. 디스크 이미지는 바꾸지 않았고, 확인용 시험 디스크만 썼다.

## 1. 규모

| 부분 | 형식 | 음성 |
|---|---|---|
| 비주얼 장면 1–7 | 그림 `VIS*_?S.PXT` 30장(640×216) + 음성 `VIS*?.AIF` 16개 | 약 33분 |
| 스테이지 대화 | 얼굴 `K_*.SPT` + 음성 `ST*_*.AIF` 58개 | 약 47분 |
| 오프닝 `SHOP210.CPK` | Cinepak 동영상 69초 | 대사 여부 미확인 |

그림 한 장이 1분 가까이 떠 있는 동안 대사가 여러 줄 지나가므로, 그림에 글자를 미리 그려 넣는 방식은 맞지 않는다. 자막은 시간에 맞춰 따로 그려야 한다.

## 2. 받아쓰기 (Whisper)

- faster-whisper large-v3, GPU, `language="ja"`, 단어 시각, VAD. 장면 1(VIS1A 155초, VIS1B 158초)에 각각 몇십 초.
- 결과: VIS1A 32구간, VIS1B 45구간. 대부분 뜻이 통하는 초안 수준.
- 고칠 것: 잘못 들은 곳(「プロとのやり方」→ プロト, 「こうつもんね」→ 好都合ね?, 「海を怪我した」), 이름 표기(シエラ/シェラ), 화자 구분 없음, 다른 화자의 대사가 한 구간에 붙음, 신음·숨소리 구간은 비어 있음.
- 결론: 사람이 원문을 듣고 고치는 단계가 꼭 필요하지만, 시작점과 시각 정보로는 충분하다.

## 3. 장면 코드 (`MAIN.BIN`, `0x06010000` 적재)

- 장면 분기 `0x06035364`: 0–5, 8 → 비주얼 장면 1–7 (`0x06033B84`, `0x06033DEC`, `0x0603407C`, `0x06034344`, `0x060345D4`, `0x060348A4`, `0x06034B0C`), 9 → 엔딩 `0x06034E30`.
- 장면 1은 **프레임 카운터 r8**로 움직이는 고정 대본이다. 카운터 값에 따라:

| r8 | 시각(60fps) | 동작 |
|---|---|---|
| 0 | 0초 | 그림 4장 불러오기(`0x06030E78`), 그림 1 표시, 페이드 인 120, `vis1a.aif` 재생(`0x06010EB8`) |
| 3900 | 65초 | 페이드 아웃 60 |
| 4380 | 73초 | 그림 3 표시, 페이드 인 60 |
| 6300 | 105초 | 페이드 아웃 60 |
| 6900 | 115초 | 그림 2 표시, 페이드 인 60 |
| 9000 | 150초 | 페이드 아웃 120 |
| 9600 | 160초 | 그림 4 표시, `vis1b.aif` 재생, 페이드 인 120 |
| 18600 | 310초 | 페이드 아웃 60 |
| 19200 | 320초 | 장면 끝 |

  VIS1A 길이(155초)·VIS1B 시작(160초)·끝(318초)이 이 표와 맞는다. **자막 시각 = 음성 시작 프레임 + 받아쓰기 시각 × 60**으로 정할 수 있다.
- 프레임마다 `0x0604A500`(수직 동기 대기)을 부른다(`0x06033D42`, 리터럴 `0x06033D94`). 자막 코드를 끼울 자리 후보.
- 그림 불러오기 `0x06030E78(파일 이름)`: 파일 크기 → 힙 할당 `0x0602F4A4(크기, 2)` → 핸들을 주소로 `0x0602FC64` → 읽기 `0x06010CD4`. 장면 끝에 `0x0602FB64(핸들)`로 해제. 자막 데이터 파일도 같은 함수로 불러올 수 있다.

## 4. 실행 중 상태 (장면 1 시작 약 25초, Mednafen 세이브 스테이트)

- 힙 풀(`0x060700D0` 표): 상위 RAM `0x0608E000–0x06100000`, 하위 RAM `0x00200000–0x00300000`. 이 시점 빈 곳은 상위 약 186KB, 하위 약 380KB. 자막 데이터는 게임 할당기로 받으면 겹칠 위험이 없다.
- 스택 `0x06001F60` 부근. CPU는 수직 동기 대기 루프(`0x0604A51A`).
- **VDP1은 장면 중 아무것도 그리지 않는다**(명령표 첫 칸이 끝 명령 `0x8000`). TVMR = 1(8bpp, 640폭 고해상도 모드). 엔딩은 같은 조건에서 그림 위에 스태프 롤 스프라이트(`SR.SPT`)를 겹치므로, 자막도 VDP1 스프라이트로 그림 위에 얹을 수 있다.
- VDP2: 640×240(HRes 2, VRes 1), 그림은 화면 가운데 640×216, 위아래 12줄씩 검은 띠.

## 5. 아직 못 정한 것

1. **상주 코드 자리**: 프레임마다 불릴 짧은 연결 코드(수십~백여 바이트)를 둘 곳.
   - `MAIN.BIN` 끝(`0x0606AF6C`) 바로 뒤는 BSS로 쓰인다(시작 코드가 지움). 섹터 여유 148바이트는 쓸 수 없다.
   - `0x0605DAB0–0x06065AB0`(0x8000바이트, 파일에서도 0)은 파일 함수들이 쓰는 버퍼다.
   - 정적 분석으로 "아무 데서도 부르지 않는 함수"를 찾으면 548개가 나오는데, 함수 포인터 표로 불리는 경우가 많아 믿을 수 없다. 실제로 안 쓰이는 코드를 확인하거나, 장면 함수 7개의 같은 코드를 하나로 합쳐 자리를 만드는 방법이 남아 있다.
2. **글자 위치와 크기**: 아래 검은 띠는 12줄뿐이라 한 줄(스태프 롤과 같은 크기)만 들어간다. 두 줄이면 그림 아래쪽에 반투명 띠를 깔고 겹쳐야 한다.
3. **VDP1 VRAM 빈자리**: 장면 중 VDP1 VRAM 사용량, 자막 텍스처를 둘 위치.
4. **디스크 공간**: 트랙 1 끝에 빈 섹터가 150개(약 300KB)뿐이다(마지막 파일 끝 LBA 96858, 트랙 97008). 장면 7개 자막 그림이 여기에 들어가는지 계산해야 하고, 모자라면 1비트 글자 + 압축을 쓰거나, 트랙 1을 늘리고 뒤 오디오 트랙을 밀어 CUE를 새로 쓰는 방법이 있다(BIN/CUE 배포라면 가능, 원본 섹터 배치 보존 원칙과는 충돌). ISO에 파일을 추가하는 빌드 기능도 새로 필요하다.
5. 장면 2–7이 같은 구조인지(장면 1만 읽음).

## 7. 2단계: 장면 1 자막 표시 시험 (2026-10-03) — 성공

시험 디스크(장면 1로 바로 부팅)에서 그림 아래 띠에 한글 자막이 대사에 맞춰 바뀌는 것을 Mednafen으로 확인했다. 5절의 미정 사항은 아래처럼 정했다.

### 7.1 상주 코드 자리 — `0x06086340–0x0608E000` (약 31KB)

- BSS 끝(`_end`, `0x06086334`, 시작 코드 `0x0601002C`의 섹션 표)과 게임 힙 시작(`0x0608E000`, 코드 상수 `0x0603171C`) 사이.
- 이 구간을 가리키는 코드가 MAIN.BIN·FILEX.BIN 어디에도 없다. 유일한 사용자는 libc `sbrk`(`0x0605CF4C`, 포인터 `0x060730C8`)인데, 이를 부르는 `malloc`(`0x0605CC58`)을 부르는 곳이 없다(링크만 된 죽은 코드). 실행 중 sbrk 포인터는 0, 구간 전체도 0.
- 부팅 때 지워지지 않으므로 처음 한 번 디스크에서 읽어 들인다.

### 7.2 연결 코드 — 쓰이지 않는 라이브러리 버전 문자열 3곳(각 32바이트)

`SYS Version 2.53`(`0x06054398`), `CDC Version 1.22`(`0x06059560`), `BUP Version 1.25`(`0x0605A36C`)는 가리키는 포인터가 없다.

| 자리 | 내용 |
|---|---|
| SYS | 빠른 길: `BASE+0x10`의 확인 값이 맞으면 `BASE`로, 아니면 CDC로 (10명령 + 리터럴 3개) |
| CDC | 느린 길: `0x06010CD4("SUB.BIN", BASE)`로 읽은 뒤 `BASE`로 |
| BUP | 파일 이름 `SUB.BIN` |

장면 함수의 리터럴 두 개만 바꾼다(장면 1: `0x06033CF4` 그림 로더 `0x06030E78` → SYS, `0x06033D94` 수직 동기 대기 `0x0604A500` → `BASE+0x0A`).
- 그림 로더 훅: 장면은 0프레임에 **음성을 틀기 전에** 그림을 불러오므로, 이때(CD가 한가할 때) `SUB.BIN`과 장면 자막 데이터 `SUBn.DAT`를 읽는다. 음성 재생 중에 CD를 읽으면 음성 스트림을 깨뜨릴 수 있어 이 시점을 골랐다.
- 프레임 훅: 원래 대기를 부른 뒤 r8(장면 프레임 카운터)로 현재 자막을 정해 그린다.
- 캐시: 확인 값을 읽을 때 `BASE+0x10` 줄이 캐시에 들어갈 수 있으므로, 확인 값을 첫 캐시 줄 밖에 두고 첫 줄(16바이트) 안에서 캐시 전체를 비운다(CCR `0xFFFFFE92` CP 비트). 데이터 파일을 읽은 뒤에도 비운다. 첫 시험에서 CCR 주소를 `mov #-110`(= `0xFFFFFF92`)으로 만들어 주소 오류로 멈췄다 — 16비트 리터럴 `0xFE92`로 고침.

### 7.3 그리기 — VDP2 비트맵에 CPU로 직접

- 장면 화면은 NBG0 하나, 1024×256 RGB555 비트맵(VRAM 0번지, 한 줄 2048바이트). 그림은 12–227줄, 0–11줄과 228–239줄은 `0x0000` 띠. 페이드는 색 오프셋(CLOFEN)이라 자막도 함께 어두워진다.
- 자막은 아래 띠 228–239줄에 한 줄. 줄이 바뀔 때만 띠를 지우고 다시 그린다. 띠 오른쪽 끝 화소(639, 239)에 표지 `0x0001`을 두어, 누가 띠를 덮어쓰면 다시 그린다.
- VDP1·SPT 체계(스태프 롤이 쓰는 `0x060111DC`/`0x06012118`/`0x060320F0`, VRAM 캐시 관리)는 건드리지 않는다.

### 7.4 데이터와 코드

- `SUB.BIN`(744바이트): C + 진입 어셈블리, WSL Ubuntu `sh4-linux-gnu-gcc -m4-nofpu -mb`(`-m2` 미지원)로 빌드. 결과를 objdump로 검사해 SH-2에 없는 명령(`shad`/`shld` 등)이 있으면 거부 — GCC가 상수 시프트도 `shad`로 바꾸므로 홀수 시프트는 인라인 어셈블리로 고정.
- `SUBn.DAT`: 장면에 나오는 글자만 2bpp(4단계) 글리프로(24줄 정사각으로 그려 세로를 절반으로, 스태프 롤과 같은 방식), 줄마다 시작·끝 프레임과 글리프 번호. 장면 1: 84줄, 글자 264개, 20,856바이트(한도 27,840).
- 디스크: 트랙 1 끝 빈 섹터(LBA 96858–)에 파일을 쓰고 루트 디렉터리를 이름 순으로 다시 짠다(6섹터 유지). FILEX는 부팅 때 디렉터리를 RAM 표(`0x0600E160`, 24바이트 항목, 용량 258)에 올리며 새 파일도 정상으로 읽혔다.

### 7.5 시각 맞추기

- 장면 중 프레임 비율은 **59.826Hz**(녹화 음성 샘플 수로 잼). 60으로 계산하면 VIS1B 끝에서 0.46초 어긋난다.
- 음성 지연: Mednafen 녹음과 AIF를 상호상관(일치도 0.69–0.72)해 보니, 음성 0초는 재생 호출보다 VIS1A **39프레임(0.65초)**, VIS1B **55프레임(0.92초)** 늦게 들린다(CD 찾기 시간, 파일 위치마다 다름). VIS1A 앞(14초)·뒤(140초) 구간이 같은 시작점을 주므로 음성 속도 어긋남은 없다. 자막 시각 = 재생 프레임 + 지연 + 음성 시각 × 59.826 − 0.1초.
- 지연은 음성 파일마다 재야 한다. 영상 녹화(PNG)는 에뮬레이션을 1/4 속도로 늦추므로, 소리만 녹음(`-soundrecord`, 실시간)하고 두 재생 호출의 프레임 간격과 비교하는 방법이 빠르다.

## 8. 3단계: 정식 빌드, 장면 1–7 (2026-10-03)

7.4–7.5의 시각 방식(장면 프레임 카운터 r8 + 미리 잰 지연)은 아래 이유로 바꿨다.

- **r8은 그림 전환 때 밀린다.** 세이브 스테이트 두 개 사이 SCSP `GlobalCounter`(44100×32Hz, 에뮬레이션 시계)로 89.777초가 지났는데 r8은 5329만 늘었다(실제 5371). 그림 압축을 푸는 동안 프레임 루프가 멈춰 한 번에 약 21프레임씩 밀린다. 그림 전환이 없는 구간에서는 정확히 59.826fps.
- **실제 수직 동기 카운터** `0x060730D0`(u32, `0x06010664` 인터럽트 처리에서 1씩 증가)는 같은 구간에서 정확히 5371 늘었다.
- **음성이 울리기 시작한 순간을 직접 잡는다.** 음성 스트림은 SCSP 슬롯 12(사운드 RAM `0x28000`, 8192샘플 링, 22050Hz, 반복)로 나온다. 진단판 SUB.BIN으로 재생 호출 뒤 매 프레임 32개 슬롯의 키온을 기록했더니, 슬롯 12가 VIS1A는 호출 **39프레임** 뒤(영상 녹화로 잰 지연과 같음), VIS1B는 **24프레임** 뒤에 켜졌다(앞서 계산한 13은 틀림). CD 찾기 시간은 실기와 에뮬레이터가 다를 수 있으므로 미리 재지 않고 실행 중에 감지한다.

최종 구조:
- 장면마다 리터럴 세 종류를 바꾼다: 그림 로더 `0x06030E78` → SYS 연결 코드, 수직 동기 대기 `0x0604A500` → `BASE+0x0A`, 음성 재생 `0x06010EB8` → `BASE+0x14`(호출 순간 기록 후 원래 함수로). 장면 1–7 리터럴 위치는 `tools/steamhearts/subtitles.py`의 `SCENES`.
- 자막 기준 = 재생 호출 뒤 슬롯 12가 키오프→키온 되는 프레임(120프레임 안에 못 보면 호출 + 39). 줄은 그 기준에서 `(시작 − 0.1초) × 59.826` 프레임에 뜬다.
- 장면 번호는 그림 로더가 받는 파일 이름의 숫자(`vis3_1s.pxt` → 3)로 정한다. 장면 번호 변수 `0x0605D710`은 시험 디스크에서 0으로 남아 쓰지 않는다.
- 빌드: `khpatch.py build`의 `subtitles` 구성요소. MAIN.BIN은 같은 크기로 교체, `SUB.BIN`(1,036바이트)과 `SUB1.DAT`–`SUB7.DAT`(12–21KB)는 LBA 96858부터, 루트 디렉터리는 이름 순으로 다시 짠다(크기 변경만 있을 때는 기존처럼 제자리 수정 → `--subtitles original` 대조군은 원본과 바이트 단위로 같음).

확인:
- 장면 1–7 시험 디스크: 모두 멈춤 없이 재생, 각 장면의 자기 대사 표시(스크린샷).
- 장면 1 녹화(영상+소리): 첫 줄·둘째 줄 자막이 대사보다 **0.084초** 먼저 뜸(설계 0.1초, 그리기가 다음 프레임에 반영되는 1프레임 차).
- 아직: 정상 플레이로 장면에 들어갔을 때, 장면 2–7의 시각 녹화 대조, 실기.

번역: `translation/voice/vis1.json`–`vis7.json` 502줄. 일본어는 Whisper 받아쓰기를 고치지 않은 것, 한국어는 초안(`needs_review`). 받아쓰기를 문맥으로 고친 줄은 `asr_uncertain`, 알아들을 수 없는 조각과 Whisper 환각(장면 끝 「ありがとうございました」 등)은 뺐다.

## 9. 스테이지 대화 자막 시험 (2026-10-03) — 화면 표시 성공

스테이지 안 대화(얼굴 그림 + 음성 `ST*_*.AIF`)는 비행 중에 오가고, 화면 아래 왼쪽·오른쪽에 얼굴이 뜬다. 스테이지 화면은 320×224, VDP2 NBG0·NBG1만 쓰고 NBG2·NBG3는 꺼져 있다.

- **글자 면**: 비어 있는 NBG3를 4bpp 1×1 셀 면으로 켠다. 맵 VRAM `0x70000`, 글자 `0x74000`(뱅크 B1, 스테이지에서 비어 있음), 팔레트는 CRAOFA N3 오프셋 7 + 팔레트 15(CRAM `0x7F0`–, 스테이지에서 비어 있음), 우선순위 7, 사이클 패턴 CYCB1 T4/T5에 N3 이름/글자 읽기. 처음 CRAOFB(회전면·스프라이트용)에 오프셋을 써서 글자가 검게 나왔다 — NBG0–3은 CRAOFA.
- **레지스터는 쓰기 전용**이라 읽어서 고치면 NBG0/1 설정이 깨진다(실제로 배경이 사라짐). SEGA VDP2 라이브러리가 매 프레임 RAM 사본에서 올리는 것을 업로드 루틴(`0x0604B728`)에서 확인: 레지스터 `0x0E`–`0x27` ← `0x060859B0`+레지스터, `0x28`–`0x6F` ← `0x060859B8`+레지스터, `0x70`–`0xAF` ← `0x06085B10`+레지스터, `0xE0`– ← `0x06085B80`+레지스터. 업로드 직후 사본 값에 NBG3 비트만 더해 다시 쓴다.
- **훅 두 개를 실행 중에 설치**: SUB.BIN은 이제 부팅 직후 게임 로고 그림을 읽을 때 올라온다(`0x060164D0` 안의 그림 로더 리터럴 `0x060165C0` → 연결 코드). 올라오면 SUB.BIN이 RAM에서 수직 동기 처리의 마지막 호출(`0x06010828`: `0x06010578` → BASE+0x18)과 VDP2 라이브러리의 업로드 호출(`0x0604B9E4`: `0x0604B728` → BASE+0x1C)을 바꿔 넣는다. 디스크의 MAIN.BIN에는 이 둘을 넣지 않는다(부팅 때 SUB.BIN이 아직 없음).
- **스테이지 시작 때 VRAM·CRAM이 지워진다** → 맵 첫 칸과 팔레트를 매 프레임 확인해 지워졌으면 다시 그린다.
- 시험판(`-DSTAGETEST`, 고정 한 줄)으로 스테이지 1에서 얼굴 바로 위(y 120)에 13픽셀 한글 + 검은 테두리 표시 확인. 정식 빌드(1,200바이트, 훅만)로 비주얼 장면·타이틀·스테이지 정상 진행 확인.

### 9.1 정식 구현 (같은 날)

- **음성**: 스테이지 공용 코드의 음성 재생 리터럴 4곳(`0x0601AD98`, `0x0601AF10`, `0x0601B080`, `0x0601B29C`)도 SUB.BIN이 실행 중에 재생 훅으로 바꾼다. 재생 함수가 받는 파일 이름(`st1_03.aif`)으로 대사를 고른다. 시각 기준은 비주얼 장면과 같은 슬롯 12 키온(스테이지 1 첫 음성: 호출 57프레임 뒤, 데이터 읽기 포함).
- **데이터 읽기**: 스테이지 번호 변수(`0x0605D710`)는 장면 분기를 보면 스테이지와 1:1이 아니어서 쓰지 않는다. 그 스테이지의 첫 음성이 재생될 때 이름의 숫자로 `STGn.DAT`를 읽는다. 스테이지 음성은 CD에서 흘려 읽으므로 배경음악이 CD 음악일 수 없고, 재생 직전에 작은 파일을 읽어도 충돌하지 않는다.
- **글자 조립**: 글리프는 13픽셀 글꼴을 16줄 칸에 그리고 테두리까지 상자 안에 넣은 2bpp(0 투명, 1 검은 테두리, 2 회색, 3 흰색). 대사가 바뀔 때 수직 동기 처리 안에서 RAM 버퍼(`0x0608CC00`, 셀 160개)에 조립해 VRAM에 복사한다. 304픽셀을 넘는 줄은 가운데 근처 띄어쓰기에서 두 줄로 나누고, 한 줄짜리는 아래 줄(얼굴 쪽)에 둔다. 위치는 맵 12–15행(y 96–127): 14행부터 두면 아래 줄 끝이 얼굴 그림(y 134–)에 가려졌다.
- **데이터**: `translation/voice/st1.json`–`st8.json` 376줄, `STGn.DAT` 8–21KB(한도 22,720 = 셀 버퍼 앞까지). 효과음만 있는 `ST3_04`, `ST5_04`, `ST5_05`, `ST5_FD`, `ST5_03`은 Whisper가 「次回予告」를 지어내 자막을 넣지 않았다. `_BD`·`_FD`는 보스전 패배 대사로 보인다.
- **확인**: 스테이지 1을 정상 플레이로 진행하며 대사 진행에 맞춰 자막이 바뀌는 것을 확인. 스테이지 2–8은 데이터만 만들었고 화면 확인은 아직.

### 9.2 스테이지 2–8 화면 확인과 게임 오버 수정 (2026-10-05, v0.2.1)

- **확인용 디스크**: 타이틀에서 정상으로 시작하되, 모드 1(스테이지) 진입 처리 `0x06033A00`의 `mov.l @(…),r1 / mov.w r8,@r1`(`0x0605D728` ← 0)을 `mov #N,r1 / mov.w r1,@r9`(`E10N 2911`, r9 = 진행 번호 `0x0605D710`)로 바꿔 진행 번호를 고정한다(`work/tools/testdisc.py 0 --patch 0x23A00=e10N2911 --patch 0x239B4=e100 --patch 0x23A56=6491`). 부팅 때 모드를 1로 바꾸면(`--stage`) 플레이어 준비가 안 돼 바로 게임 오버가 된다. 타이틀 다음의 START STAGE 화면은 그대로 넘긴다.
- **진행 번호 → 스테이지**: 0–5 = 스테이지 1–6, 6 = 스테이지 7 앞 구간(`st7_00`부터), 7 = 스테이지 7 뒤 구간(`st7_02`부터), 8 = 스테이지 8(최종 보스, `st8.aif` 하나). 장면 번호 0–5·8이 비주얼 장면 1–7인 것과 맞는다.
- **확인**: Mednafen을 키 입력(스캔 코드)으로 자동 조작해 진행 번호 0–8을 각각 약 1분 반씩 돌리고 세이브 스테이트 미리보기를 모았다. 모든 스테이지에서 시작 대사 자막이 음성 진행에 맞춰 바뀌고, 두 줄 나눔도 정상. 스테이지 8은 대사가 이어하기 화면 중에도 계속되며 자막도 따라간다. 보스 직전·격파(`_BD`·`_FD`) 대사는 기체가 거기까지 못 가서 아직 못 봤다.
- **버그와 수정**: 스테이지 2에서 게임 오버가 되자 끝난 `ST2_00` 대사 자막이 처음부터 다시 나왔다. 자막 없는 음성(쓰러질 때의 `deadblow.aif`·`deadfala.aif`로 보임. 스테이지 코드가 대사와 같은 재생 함수에 넘긴다)이 장면용 경로로 빠져 `start_watch(0)`을 부르고, 그 키온이 `anchor[0]`을 새로 잡는데 `stage_voice`는 이전 대사로 남아 있었기 때문. 이름이 `stN`이 아닌 음성에서는 `stage_voice = -1`로 끊는다. 처음에는 `GAME_MODE == 1`일 때만 끊게 했다가 비주얼 장면 자막이 사라졌다 — **장면 모드 처리(`0x06033A44`)가 들어오자마자 모드 값을 1로 바꾸므로 장면 중에도 `GAME_MODE`는 1**이다. 장면 경로(`nplay`)는 그대로 두고 대사 선택만 끊는 것으로 고쳤다(SUB.BIN 2,800바이트).
- **기타**: 번역에 있는 `ST5_01`·`ST7_04`는 MAIN.BIN에 파일 이름이 없어 게임이 재생하지 않는다(자막 데이터만 남음, 해 없음). 스테이지 8의 보스전 패배·격파는 `st7_bd`·`st7_fd`를 다시 쓰므로 그때 `STG7.DAT`를 읽어 같은 대사 자막이 나올 것으로 보인다(코드로만 확인).

### 10.1 비주얼 장면 자막 잘림 — 원인

자막을 그림 아래 검은 띠(228–239줄)에 그렸다. 세가새턴 화면은 240줄이지만 TV·많은 에뮬레이터(Beetle Saturn 기본 8–231줄, 스팀덱 화면 비율 조정 등)는 위아래를 잘라 224줄만 보인다. 228줄부터는 그 밖이라 글자 윗부분만 남았다. Mednafen 설정이 0–239줄 전부 보이게 되어 있어 확인 때 놓쳤다.

### 10.2 실기에서 스테이지 자막이 안 나옴 — 원인

스테이지 글자 면으로 켠 NBG3가 VDP2 VRAM 읽기 시점 규칙을 어긴다. 스테이지의 사이클 패턴(`CYCA0/B0` = `4444 5555`)은 NBG0·NBG1 문자 읽기를 축소 1/2 설정에 맞춰 T0–T7 거의 전부에 걸어 둔 상태라 빈 시점이 B1 뱅크의 T4–T7뿐이다. 거기에 NBG3 패턴 이름(T4)·문자(T5)를 넣었는데, 일반 해상도에서 T4 패턴 이름 읽기에 짝지을 수 있는 문자 읽기는 T0–T3뿐이다(ST-058 표 3.4). 에뮬레이터는 이 규칙을 따지지 않아 표시되지만, 실기는 NBG3를 그리지 못한다. 빈 시점이 T4–T7뿐이라 규칙을 지키면서 NBG3를 켤 방법이 없다.

### 10.3 고친 방식 — 자막을 VDP1 스프라이트로

- **VDP1 VRAM 확보**: 게임은 부팅 때(`0x06031674`) VDP1 VRAM `0x08040–0x80000`을 텍스처 힙(풀 2)으로 잡는다. 끝 상수(`0x06031730`, `0x05C80000`)를 `0x05C7E000`으로 바꿔 끝 8KB(`0x7E000–0x7FFFF`)를 자막 텍스처 전용으로 뺐다. 끝에 표지 워드 `0x4B48`을 두고 누가 지우면 다시 올린다.
- **글자**: 장면 글리프는 2bpp 그대로(SUBn.DAT 크기 유지), SUB.BIN이 한 줄을 RAM(`0x0608CC00`)에서 4bpp 텍스처로 조립하면서 검은 테두리(옆 2화소, 위아래 1줄)를 붙인다. 스테이지 글리프는 테두리가 들어 있는 기존 데이터.
- **장면**: 장면 중 VDP1은 아무것도 그리지 않으므로, VDP1 VRAM 0번지에 시스템 클리핑·로컬 좌표·스프라이트·끝 명령을 직접 쓴다(명령 0은 맨 마지막에 써서 VDP1이 반쯤 쓴 목록을 보지 않게). 위치는 그림 아래쪽 212–225줄(224줄 화면 안). 장면 설정(`0x06035364`)이 스프라이트 색 계산을 더하기 모드로 켜 두어(CCCTL `0x0540`) 검은 테두리가 그림에 더해져 사라졌다 → 장면 중에는 CCCTL의 SPCCEN을 끈다(레지스터와 VDP2 라이브러리 RAM 사본 `0x06085C6C` 둘 다. 장면은 레지스터를 다시 올리지 않는다). 장면이 끝나면(프레임 훅이 30 vblank 동안 안 불림) 사본이 그대로면 되돌린다.
- **스테이지**: 게임은 VDP1 명령을 RAM의 우선순위 목록 64개에 모았다가 프레임 끝(`0x060112F4`)에 묶어 DMA로 보낸다. 그 직전(호출 리터럴 4곳 `0x06032104`, `0x06032660`, `0x06033434`, `0x06033678`)에 마지막 목록(63)에 자막 스프라이트를 더한다(`0x060113D0`). 16비트 프레임버퍼(스프라이트 형식 5) 팔레트 `0x7F0`.
- **NBG3·VDP2 레지스터 손대기는 모두 없앴다**(이전 업로드 훅 제거).

### 10.4 일시정지·게임 오버 (같은 조사에서 발견)

치트로 스테이지를 돌리다 일시정지하자 자막이 계속 넘어가고 깨진 무늬가 나왔다. 일시정지 루프(`0x0603355C`–)는 목록을 한 번 저장(`0x0601123C`)하고 음성 스트림을 멈춘 뒤, 매 프레임 저장본을 되살려(`0x06011298`) 그린다. 그래서 (1) 음성은 멈췄는데 자막 시계는 흘렀고 (2) 저장본에 남은 이전 자막 스프라이트가 새 텍스처를 옛 폭으로 그렸다.
- 일시정지 루프의 되살리기 호출(리터럴 `0x06033680`)을 훅해, 그 동안 자막 시계(`anchor[0]`)를 멈춘다.
- 목록 저장 호출 두 곳(`0x06032564` 게임 오버·이어하기, `0x06033460` 일시정지)을 훅해, 저장 직전에 그 프레임에 넣은 자막 명령을 건너뛰기(CMDCTRL `0x4000`)로 바꾼다. 매 프레임 새 명령이 따로 들어간다.
- 이어하기 화면도 저장본을 되살리지만(`0x06032668`) 음성이 계속되므로(9.2절) 시계는 멈추지 않는다.

### 10.5 컴파일러

- 데비안 bookworm의 SH4 gcc 12.2는 메모리에서 읽은 값의 `if (x)`에서 비교 명령을 빼먹는다(`sh_treg_combine` 단계, `-O1` 이상). 재현: `int g; void t(void){ if (g) h = 2; }` → `tst` 없이 `bt.s`. 새 코드에서 스테이지 첫 줄이 빈 줄로 처리되는 식으로 드러났다. 이전 SUB.BIN도 같은 컴파일러였다.
- `tools/subtitle/Dockerfile`(데비안 trixie, gcc 14.2)로 빌드하고, `build.sh`는 gcc 13 미만을 거부한다. gcc 14는 범위 검사 두 개를 가변 시프트(`shld`, SH-2에 없음)로 합치는 경우가 있어 `check_sh2.py`가 잡았다 → 해당 비교를 부호 없는 비교 하나로 고쳤다.
- SUB.BIN이 4KB를 넘어(4,160바이트) 코드 자리를 `BASE`–`BASE+0x1200`으로 늘리고 자막 데이터를 `BASE+0x1200`부터 둔다(한도 22,208바이트, 가장 큰 `STG6.DAT` 21,332).

### 10.6 확인 (Mednafen 1.29.0, 화면 8–231줄 = 224줄 보기)

- 치트(타이틀 PRESS START에서 A+B+START → 스테이지 선택·EXTRA OPTION에 VISUAL TEST)로 정상 경로를 따라 확인. 출처: SEGA SATURN SHIRO "Under the microscope: Steam-Heart's"(2025-12-09).
- **비주얼 장면 1–7 (VISUAL TEST, 최종 빌드)**: 장면마다 끝까지 재생하며 약 2.4초마다 세이브 스테이트로 표시 중인 자막 번호와 VDP1 목록·텍스처 표지·CCCTL을 읽음. 502줄 중 439줄이 표본에 잡혔고, 나머지 63줄은 모두 표본 간격보다 짧은 줄(2.4초 미만). 표본 전부에서 우리 목록·텍스처가 온전하고 SPCCEN이 꺼져 있었음(코드 리뷰 반영 전 빌드에서는 그림 전환 순간 3번 우리 목록이 아니었음). 검은 테두리는 밝은 그림 위에서도 보임(`work/evidence/v022-scene1-native.png`).
- **스테이지 시작 대사 (최종 빌드, 스테이지 선택 치트)**: 선택 순서대로 스테이지 1–7, 7B, LAST BOSS를 새로 부팅해 약 100초씩 진행. 시작 음성(`ST1_00`·`ST1_01`, `ST2_00`, …, `ST6_00`·`ST6_01`, `ST7_00`)의 자막이 음성에 맞춰 나오고, 매 표본에서 VDP1 목록 속 자막 스프라이트 수가 그 줄의 줄 수와 같았음. 7B와 LAST BOSS는 `STG7.DAT`를 읽어 표시(LAST BOSS 첫 대사 확인).
- **일시정지**: 멈춘 동안 시계 정지(두 표본 사이 `now − anchor` 일정), VDP1 목록에 저장본 자막은 건너뛰기, 새 자막 하나만 그려짐. 풀면 다음 줄로 이어짐. 게임 오버·이어하기 화면도 같은 방식으로 깨짐 없음.
- **실기는 여전히 미시험**. VDP2 VRAM 시점 문제는 없앴지만 VDP1 그리기 시간·SCU DMA 순서 등 실기에서만 드러나는 것이 남을 수 있다.

### 10.7 코드 리뷰 반영

- 장면 테두리 계산이 줄마다 약 90ms(5–6프레임) 걸려, 장면이 그림 전환을 프레임 수로 세는 탓에 그림이 음성보다 밀릴 수 있었음 → 글자 화소에서만 주변을 칠하도록 바꿈.
- 스테이지 텍스처 조립·업로드를 vblank 인터럽트에서 게임 메인 루프(목록 마무리 직전)로 옮김. 인터럽트는 보일 줄 번호만 정한다.
- 음성 재생 훅에서 감시 시작을 음성 번호 기록보다 먼저 해, 인터럽트가 새 음성과 이전 기준 시각을 짝짓지 않게 함.
- CCCTL 되돌리기는 장면 데이터가 그대로일 때만. 목록 저장 때 건너뛰기 표시는 이번 목록 버퍼 범위 안의 명령에만. 정적 배열은 0으로 초기화된 `.data`로.
- sub.c의 상수와 데이터 빌더(`subtitles.py`)를 대조하는 테스트 추가, 빌드 컨테이너 기반 이미지를 다이제스트로 고정.

### 10.8 스테이지 끝까지 (무적 확인용 빌드, 2026-10-06)

- **무적**: 일시정지 치트(위위아래아래왼오왼오 B A, 표 `0x06065F08`, 처리 `0x06033346`)는 플레이어 구조체(`*(0x06077A58)` + 번호 `0x06073474` × 80) `+0x42`에 0x4B0(약 20초) 무적 시간을 넣는다. 확인용 SUB.BIN(`-DTEST_INVINCIBLE`, `out/kotest`, 제품과 분리)이 이 값을 매 vblank 다시 채워 계속 무적으로 만든다. 제품 SUB.BIN은 이 코드 없이 빌드되며 바이트 단위로 그대로다.
- `work/survey_boss.py`로 스테이지 선택 순서마다 처음부터 연사·좌우 이동 자동 진행, 약 4초마다 표시 자막 기록:

| 선택 | 결과 | 자막이 확인된 음성 |
|---|---|---|
| 1 | 보스 격파 → 비주얼 장면 1 | ST1_00–05 |
| 2 | 보스 격파 → 장면 2 | ST2_00–03 |
| 3 | 보스전에서 게임이 멈춤(아래) | ST3_00–02 |
| 4 | 보스 격파 → 장면 4 | ST4_00–04 |
| 5 | 보스 격파 → 장면 5 | ST5_00, 02, 06 (01은 게임이 안 틀고 03–05는 자막 없는 효과음) |
| 6 | 보스 격파 → 장면 6 | ST6_00–05 |
| 7 | 15분 한도 | ST7_00–03, 05–08 (04는 게임이 안 틂) |
| 7B | 보스 격파 → 장면 7 | ST7_02, 03, 05–08 |
| LAST BOSS | 격파 → 엔딩 장면 | ST7_07, 08 |

- **스테이지 3 보스 멈춤은 확인용 무적 탓**: 멈춘 상태에서 CPU는 예외 처리(`0x06000956`)에 갇혀 있었다(함수 표 `0x06065BD8` 바깥 값으로 점프). 같은 빌드에서 보스 대사 직후 무적 쓰기 명령만 RAM에서 지우고(`0x06087024` → `nop`) 이어 가자 멈추지 않고 보스전이 진행돼, ST3_03과 기체가 격추될 때의 ST3_BD 자막까지 나왔다. 계속 무적인 상태는 원래 게임에 없는 상태라 생긴 것으로 판단한다. 해킹 없는 원본·제품 디스크 자동 진행은 보스까지 가지 못해 직접 대조는 못 했다.
- **`_BD`**: 보스전에서 기체가 격추될 때의 대사(스테이지 1·3에서 무적을 풀고 확인, 자막 정상). **`_FD`**: 무적으로 보스를 깬 9번 진행 어디서도 재생되지 않았다. 어떤 조건에서 나오는지 아직 모른다(내용은 보스 쪽 대사).
- **`ST8.AIF`**(최종 보스 뒤 탈출 장면으로 보이는 대사 24줄)는 LAST BOSS 진행에서 재생되지 않았다. 9.2절의 "진행 번호 8 = ST8" 기록과 다르므로 다시 확인이 필요하다.
